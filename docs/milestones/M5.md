# Milestone 5: Integrations (read-only) + observability

Status: **sandbox part delivered 2026-11-10**: M5-01 to M5-04, M5-08 and M5-09 delivered on sandbox fixtures with the stale-data rule; live connectors (M5-05 to M5-07), Langfuse (M5-10), semantic search (M5-11) and the pilot run (M5-12) wait for the owner decisions at the end of this document. Needs real access: the owner's decision per connection (ADR-011) and sandbox or pilot credentials. Everything in M0 to M4 runs on synthetic data; M5 is the first milestone that touches a client system, and only reading.

## Goal

A connection moves through the phases `metadata -> read_only -> sandbox -> write` with recorded consent per phase; the first real KPI observations come from Rentman and QuickBooks with full lineage (source, field, sync run, timestamp); every stale or failed sync is visible as a state, never as a number; credentials never appear in the database, logs, prompts or the frontend. Write phase is out of scope for M5 (no code path exists for it).

## Scope

In:
- `packages/connectors`: a `Connector` contract (`describe()`, `testConnection()`, `listObjects(kind, since)`, `readMetrics(kpiKeys, period)`), a provider registry and a `SandboxConnector` that serves synthetic fixtures per provider until consent is `granted`. Providers: Rentman (projects, deliveries, returns, invoices), QuickBooks Online (invoices, balances, due dates), Trengo (conversation counts and response times, no message bodies), Dropbox (document metadata only: names, folders, modified dates; never contents in M5). Pumble stays an output channel.
- Migration 0008: `sync_runs` (connection, started, finished, objects read, status, error class, run id), `webhook_endpoints` (per connection, secret reference, signature verification state), `connection_phase_changes` (from, to, consent given by, reason, security check by), `kpi_observations.source_sync_run_id` for lineage; RLS and operator metadata grants; isolation tests.
- Secret handling: `credentials_metadata.secret_ref` points at a worker-side secret store (Railway variables per connection in M5; a managed secret manager is an ADR for M6). The web app never reads secrets; the worker loads them by reference inside the connector process only. Masking in logs and run events for every value that looks like a token.
- Consent flow: client admin grants a phase in the Integration Center with the scopes shown in plain language; the Security review (Quality, Risk & Compliance agent or a superadmin) is recorded before `read_only` becomes active; revocation pauses the connection and marks dependent KPIs `missing_source`.
- Worker: `connector.sync` jobs on a schedule per connection with retries, dead-letter and incident on repeated failure; observations written through `observeKpi` with `status = ok | stale_data | missing_data | error` and lineage; `connection.test` job for the consent step.
- Integration Center UI: client workspace `/c/[slug]/integrations` (connections per system with phase, consent, scopes, last sync, stale state, grant and revoke forms) and Mission Control `/mission-control/tools` (Connected Tools: all connections, phases, sync health, never config secrets).
- Observability: run traces export to Langfuse behind a feature flag (`LANGFUSE_*` only in the worker), with tenant id as a tag and content payloads masked; if Langfuse adds no value over `run_events` in the pilot, the exporter stays off (decision in M6).
- Semantic search (ADR-019): `knowledge_embeddings` partitioned per tenant plus a separate agency table, embedding calls through budget admission, retrieval filtered by RLS and logged in `retrieval_audit`; forbidden-document test for semantic search.

Out: write phase and any mutation of a client system; Dropbox file contents; Trengo message bodies; marketing and HR connectors; the Technology Intelligence Center (M6).

## Acceptance (roadmap)

Consent recorded per connection and phase; credentials never in logs, database or prompts; stale-data states visible on the CEO dashboard and in the Integration Center; a connector in `metadata` phase performs no network call; tenant isolation holds for sync runs and observations; the first real KPI value shows its source field, sync run and timestamp.

## Decisions needed from the owner before M5 starts

1. Which system is first: Rentman (recommended, it drives the pilot KPIs) or QuickBooks Online.
2. Sandbox accounts versus the pilot client's consent: M5-05 and M5-06 can be built against vendor sandboxes; the pilot read-only run (M5-12) needs the client's written consent per ADR-011.
3. Whether Langfuse is wanted at all in the pilot (M5-10) or `run_events` plus Mission Control suffice.
