# Live Agent Mission Control: build and verification record (2026-11-11 to 2026-11-12)

Scope: ADR-024. Four slices behind the existing operator gate (MFA), no change to the orchestration (pg-boss and Mastra in the worker), no second orchestrator, no WebSocket server, no vault content in the stream.

| Slice | Delivered | Verified (evidence) |
|---|---|---|
| Backend (migration 0011, core, worker) | `agent_runs.parent_run_id`; `run_instructions` with RLS and trigger (agents and terminal runs refused, consumption once); `notify_live_change()` on nine tables (identifiers only); `queueRunInstruction`, `consumePendingInstructions`, `formatInstructionsForPrompt`; executor consumes at every checkpoint and prepends the instructions to later prompts | core test (service and trigger refusals, consumption once, immutability, tenant isolation); end to end with a local simulated worker: `operator instruction queued` then `1 operator instruction(s) applied at step generate`, run succeeded; migration applied on staging by the worker pre-deploy |
| 1 Queue | PostgreSQL LISTEN client, SSE route (snapshot first, debounced fresh snapshot per notification, heartbeat), snapshot API, client hook with backoff and polling fallback, `/mission-control/live` with lanes Needs you, Running, Done today and the per-agent timeline, instruct action, nav entry | 401 without operator session; stream delivers `event: snapshot` and a second one 3 s after an insert; instruction queued from the board lands in `run_instructions` and as a run event; 14 tests; screenshots at 1280 and 390 px |
| 2 Runs and inspector | run detail API (400, 401, 404 handled), steps from checkpoint event summaries, event feed with kind filter, instructions with consumed state, approvals and incidents, controls through the audited actions, tab and selection in the URL | API checked with and without session, wrong id, unknown id; drawer opens from Runs, Queue and timeline; instruction from the drawer appears in its list; 19 tests |
| 3 Flight Map | communications and connectors in the snapshot (from event summaries the operator may read), pure graph model with sector layout, inline SVG map with activity and human edges, keyboard-accessible agent nodes that open the inspector, recent communications list | 18 nodes, 6 edges after two simulated runs, agent click and Enter open the drawer, no overflow at 390 px; 11 tests (model plus map helpers) |
| 4 Operations Deck | agents table with Run now and Pause/Resume, live event ticker, pg-boss queue counts derived from the domain tables with grant guards, schedules with Enable/Disable, department filter on every tab | schedule toggled off and on through the redirect; department filter changes counts on every tab and survives a reload; event row opens the drawer; 15 tests |

Totals: web suite 180 tests in 15 files, typecheck clean, production build passes; core 31 tests, worker 6, connectors 18, db 14. Reuse from the research: SSE route shape and backoff hook (mission-control pattern), transcript and event vocabulary (paperclip, conductor), gate and guidance UI patterns (conductor); the React Flow plus dagre graph was not needed at this fleet size and stays an option.

Not verified: behaviour behind a buffering proxy, two web replicas sharing the stream (design supports it, not load tested), delegation edges (no flow sets `parent_run_id` yet), a live model run on staging through the board (the pilot tenant has no agent schedule enabled yet).
